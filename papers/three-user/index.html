01

Compute what is needed.
Communicate only what is necessary.

Each user sees a different linear view of the same source and wants a prescribed linear function. A relay connects their information, but starts with none of its own.

LOCAL INFORMATION

Three views of one source

For a finite-field source x, user i observes w′i = xTV′i and requests wi = xTVi. The observation and demand matrices are known when the code is designed.

User i:   w′i → wi

UPLOAD

Local encoders, separate links

Each user sends one noninteractive message computed only from its own observations. The relay receives all three messages individually. The upload cost adds the three users’ contributions.

U = total upload per instance

BROADCAST / DOWNLOAD

One message serves everyone

The relay sends a common broadcast. Each user combines it with its own observations to recover its demand, with zero error for every source realization.

D = common broadcast per instance
Model scope

Exactly three users; noiseless links; fixed-length messages; arbitrary finite fields. The demands must lie in the users’ joint observation span. Costs are normalized by blocklength and measured in q-ary units. Download means the common broadcast cost, counted once.

02

Both minima. One optimal corner.

For every feasible three-user linear task, the upload–broadcast budget region is a rectangle. Achieving the best upload cost does not require sacrificing the best broadcast cost—provided the code is designed jointly.

Proven in the preprint · Theorem 1

ℛ2 = [U*, ∞) × [D*, ∞)Also equals the closed achievable budget region over all blocklengths.
U*Minimum total upload when the broadcast budget is unrestricted.
D*Minimum broadcast when the server knows the entire source—the fully informed benchmark.

A linear code attains (U*, D*) over the original field. The converse allows arbitrary nonlinear codes and arbitrary blocklengths.

How many instances must be coded together?

The minimum linear blocklength is determined exactly by the two optimal costs.

1

One instanceif both U* and D* are integers.

2

Two instancesotherwise. No larger field is needed.

Source: Theorem 1, equations (17)–(18). This integrality criterion concerns linear codes. The paper also gives a binary example requiring two instances even when nonlinear codes are allowed.

04

The choice of upload matters.

Two stages with separate minima do not automatically yield a jointly optimal system. The relay must receive the right information—not merely the fewest bits.

An upload optimum can be the wrong one.

In the binary example, a valid scalar upload is M₁ = (a, u), M₂ = b, M₃ = c. It already minimizes upload. But repeating this observation pattern forces broadcast cost at least 2 per instance, even if the relay uses nonlinear block coding.

Repeat that upload patternU = 4,   D ≥ 2

Coordinate across the two instances.

The joint code instead uploads u₁ from user 1 and v₂ from user 2. This changes which upload-optimal information reaches the relay, and makes the fully informed broadcast optimum attainable.

Jointly designed codeU = 4,   D = 3/2

Source: the preprint’s introductory example, equations (1)–(3). More generally, the construction coordinates subspace choices and the full 15-entry LCBC broadcast profile before taking its maximum.

Where does data shuffling fit?

The work is motivated by distributed computation and related shuffling problems. Its theorem optimizes two resources in the specified three-user model: total upload and common broadcast. “Shuffle” is not an additional third cost, and the result does not assert optimality for arbitrary distributed-computing or shuffling architectures.
